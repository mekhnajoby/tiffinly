Tiffinly - Technical Documentation

A comprehensive guide to the Tiffinly Food Delivery Platform based on codebase analysis.

System Overview

Tiffinly is a PHP-based web application designed to manage a meal delivery service. It operates on a subscription model, connecting customers with delivery partners. The platform is divided into three main user-facing sections: a customer portal for ordering and management, a delivery partner dashboard for handling assignments, and an admin panel for complete system oversight.

Tech Stack

Frontend

  • HTML5, CSS3, JavaScript: Standard web technologies.
  • Bootstrap: For responsive UI components.
  • jQuery & AJAX: Used for dynamic content loading and form submissions without page reloads (e.g., in ajax/cancel_meal.php).

Backend

  • PHP 8.2+: Server-side scripting language.
  • MySQL (MariaDB): Relational database for data persistence.
  • Apache: Web server hosting the application.

Integrations & Libraries

  • Razorpay: Integrated for processing partner payments (seen in manage_partners.php).
  • Session-based Authentication: Manages user login state via PHP sessions.

Core Modules & Functionalities

The application's functionality is segregated by user roles, primarily managed through distinct directories. Each feature is handled by a specific page, providing clear, modular code.

Admin Module (/admin)

Provides full control over the platform.

  • Dashboard: Overview of system statistics (admin_dashboard.php).
  • User Management: CRUD operations for all users (manage_users.php).
  • Partner Management: Onboard partners and process payments (manage_partners.php).
  • Subscription & Plan Management: Oversee subscriptions and meal plans (manage_subscriptions.php, manage_plans.php).
  • Menu & Meal Management: Control available meals and popular items (manage_menu.php, manage_popular_meals.php).
  • Delivery Oversight: Monitor pending and ongoing deliveries (manage_delivery.php, pending_delivery.php).

Delivery Partner Module (/delivery)

Portal for delivery partners to manage their tasks.

  • Dashboard: Summary of deliveries and earnings (partner_dashboard.php).
  • Order Management: View and accept new delivery assignments (available_orders.php).
  • Delivery Tracking: Track active and completed deliveries (my_deliveries.php).
  • Status Updates: Mark order status (e.g., 'Delivered') (update_delivery_status.php).
  • Earnings & History: View payment history and performance (earnings.php, delivery_history.php).
  • Issue Logging: Report problems with a delivery (log_issues.php).

Customer-Facing Module (Root & /user)

Interface for customers to interact with the service.

  • Authentication: User login and registration (login.php, register.php).
  • Subscription Management: A full suite for handling subscriptions, including browsing plans (user/browse_plans.php), configuring schedules (user/select_plan.php), customizing meals (user/customize_meals.php), and managing active subscriptions (user/manage_subscriptions.php).
  • Meal & Delivery Management: Set delivery preferences in user/delivery_preferences.php and cancel individual meals via ajax/cancel_meal.php.
  • Password Recovery: Reset forgotten passwords (forgot_password.php).

System Workflow: From Subscription to Payout

  1. Plan Selection: A customer browses plans in user/browse_plans.php and configures their subscription (plan type, schedule, dates) in user/select_plan.php.
  2. Customization & Cart: If the plan is "Premium," the user customizes their weekly menu in user/customize_meals.php. The finalized plan is saved as a pending subscription.
  3. Customer Payment: The user completes the payment via Razorpay on the user/payment.php page.
  4. Subscription Activation: Upon successful payment, the subscription status is updated to active, and a script automatically generates all individual delivery records for the entire subscription period.
  5. Order Availability: The new, unassigned subscription appears on the delivery/available_orders.php page for all delivery partners to see.
  6. Partner Acceptance: A delivery partner accepts the subscription. This single action creates all the necessary delivery_assignments for the entire duration of that subscription, linking them to that partner.
  7. Delivery Execution: The partner uses their dashboard (delivery/my_deliveries.php) to view their assigned deliveries and update their status (e.g., 'out_for_delivery', 'delivered').
  8. Payout Calculation: The admin/manage_partners.php page displays a list of all completed but 'unpaid' deliveries, grouped by partner and date. The payment amount is calculated based on logic in admin/process_partner_payment.php, which includes base rates and potential bonuses.
  9. Admin Payout: An admin initiates the payout from the [manage_partners.php] interface, triggering a payment to the partner via Razorpay.
  10. Record Update: Upon successful payout, a record is created in partner_payments, and the corresponding `delivery_assignments` are marked as 'paid'.

Security Considerations

  • Authentication: Role-based access is enforced using session variables (e.g., $_SESSION['role']), with checks at the beginning of sensitive files (auth_check.php).
  • SQL Injection: The application uses prepared statements ($stmt->prepare() and $stmt->bind_param()) to prevent SQL injection attacks, which is a critical security practice.
  • Password Security: While not directly visible, a robust system would use password_hash() and password_verify() for storing and checking user passwords.
